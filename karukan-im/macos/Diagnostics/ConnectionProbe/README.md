# 入力接続の比較用クライアント

`NSTextView` と通常の `NSTextInputContext` を使う、使い捨て入力欄だけのアプリです。
`keyDown` や入力コンテキストの生成方法は変更しません。
`NSApplication.sendEvent`、公開されているコンテキストの activate/deactivate/handleEvent、
標準テキストビューの keyDown、未確定文字・確定文字の反映を時系列で記録します。
コンテキストの計測はこのプロセス内だけで行い、元の実装をそれぞれ一度呼びます。
ログのコールバックから入力コンテキストを取得したり、接続を再開したりしません。

リポジトリのルートで実行します。

```sh
bash karukan-im/macos/Diagnostics/ConnectionProbe/build.sh
```

出力先は `.work/connection-probe-lab/` です。アプリ起動と画面操作は通常のGUIから行ってください。
出力先の絶対パスごとに異なるアプリ識別子を使い、旧版や別ワークツリーの起動先との混同を避けます。
キー送信と入力ソース選択は、前面アプリの識別子に加え、この出力先のバンドルパスも検証します。
`client-events.jsonl` は出力先に作成されます。ログには実行ID、試験番号、起動後時刻、
イベント識別子、入力コンテキストとクライアントのオブジェクトID、配信の入れ子、
フォーカス状態、文字数と固定の試験文字列との一致だけが含まれます。入力本文は保存しません。
キーコードはこの専用アプリに届いたものだけを記録します。グローバルなイベントタップは使いません。
継続利用するためのアプリではないため、試験が終わったら終了してください。

`PhysicalKeyProbe` は**利用者が明示的に許可した場合だけ**実行します。
既存のイベント送信権限、専用アプリが前面にあること、試験ウィンドウにフォーカスがあることを確認し、
いずれかを満たさなければ停止します。新たな権限の要求はしません。
送れるキーはコード内の固定リストだけです。
入力ソースを選ぶ `SelectProbeSource` とキーを生成するプロセスは分離しています。
Karukanのスキーマ3のログは `0x4b415255` を上位32ビットに持つ試験イベント識別子だけを保存します。
両端で識別子が残らない環境では、イベント時刻と試験区間で照合し、識別子の欠落を未到達と解釈しないでください。

比較は同じバイナリで次を交互に実施します。

1. Reset → Karukan → 固定の `k`、`a`、Return。本文が「か」一文字になることを基準にする。
2. 入力ソースを変えずに非アクティブ化パネルを往復する。
3. パネル内だけABCに変更し、元の入力欄へフォーカスを戻す**前**にKarukanを選ぶ。
4. 同様に、フォーカスを戻した**後**にKarukanを選ぶ。

一回のキー押下に対する `sendEventBegin` と `textViewKeyDownBegin` の数も確認します。
文字が一度でも出ることだけでは成功としません。二重配信、余分な文字、本文と未確定範囲の不一致を区別します。
他のアプリへのフォーカス移動や利用者の操作が重なった試行は比較から除外します。
`--no-context-trace` で起動した場合は公開メソッドのフックを無効にでき、計測自体の影響を比較できます。

固定の試験文字は既定で専用プロセスへ直接送ります。Raycastを開く固定ホットキーだけはHID境界へ送ります。
第三者のイベントフィルターや操作ツールの転送と重なる場合に備え、
キー名の後に `hid`、`session`、`annotated`、`pid` を指定して配信境界だけを変えられます。
`pid` も送信先は前面の専用入力アプリに固定し、同じ入力欄のフォーカス確認を行います。
境界を変えた試行は別条件として集計し、Karukan受信と本文への確定を確認してから比較に使ってください。
`run_comparison.py <出力先> hid,pid` は開始ボタンを待ってから試行ごとに配信境界を交互に変えます。
このドライバー自身がアプリを前面にしたり、比較試験を開始したりすることはありません。
開始ボタンは専用アプリから一度だけ前面化を要求し、入力欄を確認してから試験を開始します。
背景からの自動操作が前面化を認められない場合は停止します。「Preflight (no keys)」で、
入力やソース切替を行わずに確認できます。その場合は人がアプリを前面にして開始ボタンを押してください。

「Run 20 ABC-primed switches」は、英数で実際に `a` を入力した後に本文を空にし、
別プロセスの `SelectProbeSource` でKarukanへ切り替えてから `ka` とReturnを送る条件です。
最初の英字が一文字でなければ、試験入力自体が成立していないため停止します。
日本語の確定結果が想定と違えば、入力欄を消さずに停止してその接続状態を残します。
この条件でも入力ソース選択とキー生成は別プロセスです。

試験結果のファイルは開始待ちの時点で新規の状態に置き換えます。
途中のフォーカス拒否やタイムアウトも結果に保存するため、前回の成功結果を今回の結果と誤認しません。

「Reconnect text context」は回復経路を比較するための明示操作です。
通常の試験では使わず、ログから接続開始が欠けていることを確認してから比較してください。
