# このフォークで追加・変更した機能

この文書は、`develop` ブランチで本家 Karukan に対して追加・変更した、利用者向けの機能と挙動をまとめたものです。

2026-08-26 時点の `develop`（`7f6ccb5`）の変更履歴と、`upstream/main`（`2d7f4f8`）とのツリー差分を根拠にしています。本家の変更を取り込んだ結果、フォークで先に導入した機能と本家側の実装が同等になっているものもあります。そのため、現在も独自差分として残る変更と、現在は本家と共通になった変更を分けて記載します。

開発用の `AGENTS.md`、`.gitignore`、テストのみの変更は対象外です。

## 現在も `develop` 独自として残る変更

### macOS で `Ctrl+H` を Backspace として扱う

macOS の入力中に `Ctrl+H` を押すと、Backspace と同じようにカーソル直前の文字を削除します。macOS が `Ctrl+H` を制御文字として渡す場合でも、IME 側で Backspace に正規化します。

### 入力中から `Ctrl+N` / `Ctrl+P` で候補を移動する

ひらがな入力中に `Ctrl+N` または `Ctrl+P` を押すと、その場で変換モードへ入り、次または前の候補へ移動します。macOS では、アプリケーションから文字情報が渡されない場合にも物理キーから `Ctrl+N` / `Ctrl+P` を復元します。

### `→` / `Ctrl+F` で先頭の入力候補を確定する

ひらがな入力中に候補が表示されている場合、`→` または `Ctrl+F` で表示中の先頭候補を確定します。候補が表示されていない場合は、従来どおりカーソルを右へ移動します。

カーソル移動によって候補表示を閉じたときは、内部に保持した候補も破棄します。これにより、画面から消えた古い候補を後から誤って確定することを防ぎます。

### 入力中と変換開始後で候補順を維持する

入力中に候補が表示されている状態から `Space` または `↓` で変換を開始した場合、すでに表示していた候補を同じ順序で変換候補の先頭に残します。変換時にだけ生成される候補は、その後ろへ重複を除いて追加します。

学習履歴を使わずに候補を作り直す `Tab` では、この候補順の引き継ぎを行いません。

### 候補移動後の続け打ちで、選択候補を先に確定する

変換候補を明示的に移動した後で文字や数字を入力すると、選択中の候補を確定してから、そのキーを次の入力の先頭として扱います。

一方、変換モードを開いただけで候補を移動していない場合は、本家と同じく、入力した文字を現在の読みに追加して候補を絞り直します。

## フォークで導入し、現在は本家と共通になっている変更

### 候補操作の追加

- 変換中の `Ctrl+N` / `Ctrl+P` で、次または前の候補へ移動します。
- 入力中の `Ctrl+1`〜`Ctrl+9` で、画面に表示されている同じ番号の候補を直接確定します。

### ローマ字入力の編集中に変換状態を保つ

- `st` の末尾を Backspace で削除して `s` に戻した後、`a` を入力すると `さ` に変換できます。
- 未確定の子音列の途中へカーソルを移動して母音を挿入した場合も、周囲の文字位置を崩さずにローマ字変換を続けられます。たとえば `st` の間へ `a` を挿入すると `さt` になります。
- 未確定のローマ字を含む位置で Delete を使った場合、表示上のカーソル直後の文字を削除します。

### 通常の空白を半角にする

既定設定では、未入力時の通常の `Space` は半角スペースとして扱います。単独の `Shift+Space` は全角スペースを入力し、入力中の `Shift+Space` は空白幅の設定に従います。
